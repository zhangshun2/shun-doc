问题1.0.0-正则表达式匹配

概述

LeetCode 10：实现正则匹配，支持 . 与 *。* 表示前一个字符可以重复零次或多次。 本问题是经典的字符串匹配问题，其难点在于 * 字符的灵活匹配特性。解决此问题通常有两种主流方法：动态规划（DP） 和 带记忆化搜索的深度优先遍历（DFS + Memoization）。这两种方法本质上都是通过解决子问题来构建最终解，只是实现路径和思考角度略有不同。 链接：https://leetcode.cn/problems/regular-expression-matching/

输入与输出

  • 输入：字符串 s（文本）、字符串 p（模式）
  • 输出：布尔值，表示 s 是否能完全匹配 p。

题目特征与约束

  • 模式含有两类特殊符：
    • .：匹配任意单个字符。
    • *：匹配前一个元素零次或多次。
  • * 总是跟随在一个有效字符（字母或 .）之后。
  • 字符串 s 和 p 都可能为空。
  • 字符串长度通常在 1 到 20 之间，提示了解决方案的时间复杂度可能允许指数级别，但通常会优化到多项式级别。
  • 状态依赖上一个字符：特别是 * 的存在，使得当前匹配结果可能依赖于前一个字符的匹配状态，需要合理的状态转移设计。
  • 典型字符串DP问题：dp[i][j] 通常表示 s 的前 i 个字符与 p 的前 j 个字符是否匹配。

思路引导

1. 动态规划 (DP) 思路

动态规划是一种自底向上的方法，通过构建一个二维 dp 表来存储所有子问题的解。

  • DP 状态定义：dp[i][j] 表示 s 的前 i 个字符 (s[0...i-1]) 是否能与 p 的前 j 个字符 (p[0...j-1]) 匹配。
  • 基本情况 (Base Cases)：
    • dp[0][0] = true：空字符串 s 和空模式 p 互相匹配。
    • dp[0][j]：空字符串 s 如何匹配模式 p 的前 j 个字符？只有当 p 的前 j 个字符形如 a*b*c* 这种可以匹配空串的形式时才为 true。具体来说，如果 p[j-1] 是 *，则 dp[0][j] 取决于 dp[0][j-2]（* 匹配零次）。
  • 状态转移方程 (Transition Equations)：
    • 当 p[j-1] 不是 * 时：
      • dp[i][j] 为 true 的条件是：s[i-1] 和 p[j-1] 能够匹配（即 s[i-1] == p[j-1] 或 p[j-1] == '.'），并且 s 的前 i-1 个字符能与 p 的前 j-1 个字符匹配（即 dp[i-1][j-1] 为 true）。
    • 当 p[j-1] 是 * 时：
      • * 可以匹配零次：此时 dp[i][j] 取决于 dp[i][j-2]（忽略 p[j-2] 和 *）。
      • * 可以匹配一次或多次：此时 dp[i][j] 取决于 s[i-1] 和 p[j-2] 能够匹配，并且 s 的前 i-1 个字符能与 p 的前 j 个字符匹配（即 dp[i-1][j] 为 true）。
      • 综合起来，dp[i][j] = dp[i][j-2] || (match(s[i-1], p[j-2]) && dp[i-1][j])。
  • 计算顺序：通常是 i 从 0 到 s.length()，j 从 0 到 p.length()，确保计算 dp[i][j] 时，其依赖的子问题都已解决。

2. 带记忆化搜索的深度优先遍历 (DFS + Memoization) 思路

DFS + Memoization 是一种自顶向下的方法，通过递归解决问题，并使用一个记忆化结构（通常是二维数组或哈希表）来存储已解决子问题的结果，避免重复计算。

  • 递归函数定义：dfs(s_idx, p_idx) 表示 s 从 s_idx 开始的后缀是否能与 p 从 p_idx 开始的后缀匹配。
  • 基本情况 (Base Cases)：
    • 如果 p_idx 到达 p 的末尾：只有当 s_idx 也到达 s 的末尾时才匹配成功。
    • 如果 s_idx 到达 s 的末尾：只有当 p 从 p_idx 开始的剩余部分能匹配空串时才匹配成功（即形如 a*b* 的模式）。
  • 递归逻辑：
    • 判断当前字符是否匹配：s[s_idx] 和 p[p_idx] 是否匹配（考虑 .）。
    • 处理 * 字符：
      • 如果 p[p_idx+1] 是 *：
        • * 匹配零次：dfs(s_idx, p_idx + 2)。
        • * 匹配一次或多次：如果当前字符匹配，则 dfs(s_idx + 1, p_idx)。
        • 结果是两者的逻辑或。
      • 如果 p[p_idx+1] 不是 *：
        • 只有当前字符匹配，且 dfs(s_idx + 1, p_idx + 1) 为 true 时才匹配成功。
  • 记忆化：使用一个二维数组 memo[s_idx][p_idx] 来存储 dfs(s_idx, p_idx) 的结果，避免重复计算。

可能涉及的知识点拆解

  • 动态规划 (Dynamic Programming)：
    • 状态定义：如何将问题分解为相互关联的子问题。
    • 状态转移：如何从已解决的子问题推导出当前问题的解。
    • 初始化：如何设置 dp 表格的初始值，特别是空字符串的匹配情况。
  • 记忆化搜索 (Memoization Search)：
    • 递归：如何将问题表达为递归函数。
    • 缓存：如何使用数据结构（如数组或哈希表）存储中间结果，避免重复计算。
  • 字符串处理：字符比较、索引操作。
  • 逻辑判断：&& (与), || (或) 的灵活运用。

常见误区与边界条件

  • 索引越界：在访问 s 和 p 的字符时，需要特别注意 i-1, j-1, j-2, p_idx+1 等索引是否合法。
  • * 的处理：
    • * 总是匹配其前一个字符。
    • * 可以匹配零次，这意味着可以完全忽略 p[j-2] 和 p[j-1]（即 X* 模式）。
    • * 可以匹配多次，这意味着 s 的当前字符与 p[j-2] 匹配后，s 的下一个字符仍然可以尝试与 p[j-2] 匹配。
  • 空字符串匹配：s 或 p 为空时的处理，特别是 p 为 a*b* 这种形式时如何匹配空 s。
  • dp 数组大小：通常需要比字符串长度大 1，以处理空前缀的情况。
  • match 辅助函数：封装字符匹配逻辑，提高代码可读性。

复杂度直觉

  • 时间复杂度：两种方法（DP 和 DFS + Memoization）的渐进时间复杂度都是 O(M*N)，其中 M 是 s 的长度，N 是 p 的长度。因为它们都需要填充或计算 M*N 个子问题，每个子问题通常在常数时间内解决。
  • 空间复杂度：两种方法都需要 O(M*N) 的额外空间来存储 dp 表或记忆化数组。

练习建议

  • 尝试手动推导小规模的 s 和 p（例如 s="ab", p="a*b" 或 s="aa", p="a*"）的 dp 表格或递归调用栈，加深理解。
  • 比较两种解法的代码实现，理解它们在结构上的异同。
  • 思考如何处理 +（匹配一次或多次）等其他正则表达式元字符。
